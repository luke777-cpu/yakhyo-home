# 5차 검정 — 전향적 기록 프로토콜 설계

> **내부 설계 문서다.** 환자용 페이지에 옮기지 않는다.
> 이 단계는 **Delayed ON을 판정하는 단계가 아니라, 측정할 수 있는 데이터를 만드는 단계**다.
> 마찬가지로 ON Failure를 찾는 단계가 아니라 **"반응이 없었다"와 "우리가 관찰하지 못했다"를 구별할 수 있게 만드는 단계**다.
>
> 여기에는 **치료 시간표도, 복약 지시도, 자동 진단도 없다.** 관찰 프로토콜뿐이다.

**설계일: 2026-08-22**
**입력: `PHASE3-REAL-DATA-VALIDATION.md`(실측 42 에피소드) · `PHASE4-LITERATURE-DATA-COMPARISON.md`**

## 2. 기본형 프로토콜 — **제안된 안을 한 곳 수정해야 한다**

### 지시받은 안

```
복용 전 → +30분 → +60분
```

### 데이터가 반박하는 지점

이 사람의 IR 에피소드에서 **최고점까지 걸린 시간**은 이렇다 (n=20).

```
21, 22, 23, 40, 52, 62, 64, 67, 68, 71, 74, 77, 77, 78, 80, 86, 91, 94, 123, 139
                                    ↑ 중앙값 73분
```

| 관찰 종료 | 최고점을 잡은 비율 |
|---|---|
| **+60분** | **5 / 20 (25%)** |
| +75분 | 11 / 20 (55%) |
| **+90분** | **16 / 20 (80%)** |
| +120분 | 18 / 20 (90%) |

**+60분에서 끝내면 최고점을 네 번에 세 번 놓친다.**
output 90 도달시간도 중앙값 **76분**, 최솟값이 **62분**이다 — 60분 안에 도달한 사례가 하나도 없다.

3차에서 "높이축은 비교적 읽힌다"고 한 것은 **관찰이 우연히 60분을 넘긴 에피소드들 덕분**이었다.
기본형을 +60에서 끊으면 지금 잘 되고 있는 축까지 망가진다.

### 그래서 기본형은 이렇게 한다

```
복용 직전  →  +30분  →  +60분  →  +90분
```

| 관찰점 | 무엇을 잡는가 |
|---|---|
| **복용 직전** | 기준점. 이게 없으면 상승폭 자체를 계산할 수 없다 (3차에서 42건 중 9건이 여기가 비었다) |
| **+30분** | 상승 시작 여부. →50 도달의 p25가 34분이라 이 지점이 상승 전/후를 가른다 |
| **+60분** | 상승 진행 정도 |
| **+90분** | **최고점.** 이 한 점이 기본형의 핵심이다 |

**네 점이다.** 지시받은 세 점에서 하나만 늘었고, 그 하나가 지금 유일하게 잘 재고 있는 축을 지킨다.

## 3. 정밀형 프로토콜

```
복용 직전 → +15분 → +30분 → +45분 → +60분 → (아직 낮으면) +90분 → +120분
```

**목적은 첫 상승 시각을 절단에서 꺼내는 것이다.**
→50 도달시간이 `1, 21, 23, 28, 33, 38, 38, 39, 40, 44, 45, 52, 53, 53, 62, 67, 77, 78` (중앙값 42분)이므로,
**+15와 +30 사이에 상승 시작이 놓이는 경우가 많다.** 이 두 점이 있어야 "그 사이에 올랐다"고 말할 수 있다.

+90 / +120은 **"아직 낮을 때만"** 이 아니라 **최고점을 못 잡았을 때도** 이어간다.
최고점이 90분을 넘긴 사례가 20건 중 4건 있다(91 · 94 · 123 · 139).

### 언제 정밀형을 쓰는가

| 상황 | 이유 |
|---|---|
| **아침 첫 복용** | 문헌이 delayed ON을 첫 아침 복용에서 가장 많이 다룬다. 하루 중 앞선 복용이 가장 오래 전인 구간이다 |
| **Delayed ON 의심** | 늦게 들었다고 느낀 날. 그날 하루만 정밀형으로 |
| **ON Failure 의심** | 안 들었다고 느낀 복용. 관찰이 있어야 "없었다"고 말할 수 있다 |
| **하강 중 추가복용** | §5. 최저점이 이르게 오므로 성긴 간격으로는 못 잡는다 |

### 시각은 정확할 필요가 없다

**±5~10분 어긋나도 된다.** 중요한 것은 알림이 뜬 시각이 아니라 **실제로 기록한 시각**이다.
저장은 언제나 **실제 기록 시각 그대로** 한다. 알림 예정 시각으로 반올림하지 않는다.
(3차에서 복용 시각조차 49건 중 3건만 실제 기록으로 확정되어 있었다. 같은 실수를 반복하지 않는다.)

**숫자 cutoff로 Delayed ON을 자동판정하지 않는다.** 4차에서 문헌의 기준이 30분 / 40분 / 정상 45~60분으로
서로 어긋난다는 것을 확인했다. 프로토콜은 **재는 도구**이고, 판정은 이 문서의 일이 아니다.

## 4. 아침 첫 dose 프로토콜 — 두 축을 분리한다

4차 Q5에서 확인한 대로, 표준 PD home diary는 **기상 상태**와 **첫 복용 반응**을 서로 다른 값으로 다룬다.
(근거 문헌은 원문 미확인이나, 두 값을 나누는 것 자체는 측정 논리로도 정당하다.)

### A축 — 기상 상태

| 기록 | 비고 |
|---|---|
| **기상 시각** | |
| **기상 직후 output** | 3차에서 `wake` 기록 10건의 output이 전부 20 또는 30이었다. 이 축은 이미 안정적으로 잡히고 있다 |

### B축 — 첫 복용 반응

| 기록 |
|---|
| **첫 복용 시각** (실제 시각) |
| **+15 / +30 / +45 / +60분** (정밀형) |
| 필요 시 +90 / +120 |

### 두 축 사이

**기상 → 첫 복용 사이의 간격**이 세 번째 값이다. 이 값 자체가 A축의 길이다.

> **Morning OFF와 Morning akinesia를 자동으로 구분하지도, 같다고 하지도 않는다.**
> 4차에서 두 번째 검색도 "EMO = 첫 복용 전 / akinesia = 첫 복용의 delayed ON" 방향으로 수렴했지만
> **두 번 다 원문 미확인**이라 사이트 표현을 되돌리지 않았다. (`PHASE4` §5)
> 프로토콜이 하는 일은 **두 구간을 따로 남기는 것**까지다. 이름 붙이기는 나중 일이다.

## 5. 하강 중 복용 프로토콜 — `decline → nadir → rebound`

### 데이터가 말하는 것: 최저점이 이르다

3차에서 반등까지 관찰된 세 사례다.

| # | 복용 전 | 관찰 | 최저점 시각 |
|---|---|---|---|
| **#17** | 30 | `+10:10` → `+37:40` → `+62:80` → `+82:70` → `+143:60` | **+10분** |
| **#21** | 50 | `+18:30` → `+52:50` | **+18분** |
| **#14** | 50 | `+45:30` → `+52:30` → `+65:50` → `+111:70` | **+45분** |

**최저점이 +10분, +18분에 왔다.** 기본형(`+30 / +60 / +90`)이었다면 #17과 #21의 최저점을 **완전히 놓쳤을 것**이고,
그러면 곡선은 "복용 후 그냥 올라간 것"으로 보여 **`decline → nadir → rebound` 구조 자체가 사라진다.**

### 그래서 하강 중 복용은 정밀형 + 이른 점

```
복용 직전 → +10분 → +20분 → +30분 → +45분 → +60분 → +90분 → (반등 없으면) +120분
```

기록할 여섯 값은 이렇다.

| # | 값 | 왜 |
|---|---|---|
| 1 | **복용 직전 output** | 하강의 출발점 |
| 2 | **계속 내려가는가** | `+10 / +20`이 이 답을 만든다 |
| 3 | **최저 output** | |
| 4 | **최저점 시각** | 3건 중 2건이 +20분 안에 왔다 |
| 5 | **다시 올라가기 시작한 시각** | #17은 +37분, #14는 +65분 |
| 6 | **최고 output** | 반등이 어디까지 갔는지. #17은 80까지 갔고, 그래서 no-ON이 아니다 |

### 판정하지 않는다

프로토콜은 이 여섯 값을 남기는 데까지다.
`늦게 반등 / 낮게 반등 / 반등 없음`의 후분류는 **값이 모인 뒤** 하는 일이고,
그때도 **ON Failure와 같은 것으로 취급하지 않는다.**

## 6. Episode quality — A / B / C

> **이것은 기록 완성도 기준이지 의학적 반응 기준이 아니다.**
> Grade C는 "반응이 나빴다"가 아니라 **"판정할 자료가 없다"**는 뜻이다.
> Grade A라고 해서 반응이 좋았다는 뜻도 아니다.

| 등급 | 조건 | 무엇을 할 수 있나 |
|---|---|---|
| **A** | 복용 직전 기록 있음 **AND** 복용 후 기록 3건 이상 **AND** 그중 1건이 **+30분 이내** **AND** 다음 레보도파 복용 전까지 최소 +90분 관찰 | 시간축·높이축 **둘 다** 해석 가능. 첫 상승이 절단되지 않는다 |
| **B** | 복용 직전 기록 있음 **AND** 복용 후 기록 2건 이상 | 높이축만 해석 가능. 시간축은 절단 가능성 표시 |
| **C** | 위 어느 것도 아님 | **판정 불가.** ON Failure 후보로도 올리지 않는다 |

### ON Failure 검토 자격은 별도 플래그

`evaluable` / `not evaluable` 두 값만 둔다. 정확한 cutoff는 **아직 정하지 않는다.**

| 값 | 조건 |
|---|---|
| **`evaluable`** | 복용 직전 기록 있음 **AND** 복용 후 기록 2건 이상 **AND** 다음 추가복용 전까지 관찰이 이어짐 |
| **`not evaluable`** | 그 외 — **낮은 기록 1건만으로 ON Failure 후보를 만들지 않는다** |

3차의 ON Failure 후보 3건(#4 · #9 · #10)은 전부 `not evaluable`이 된다. **그것이 옳은 결과다.**

### 현재 데이터를 이 기준에 대입하면

| 조건 | 42건 중 |
|---|---|
| 복용 직전 기록 있음 | 33 |
| 복용 직전 + 후속 2건 이상 (**Grade B 이상**) | **18 (43%)** |
| 복용 직전 + 후속 3건 이상 | 12 (29%) |
| **+30분 이내 관찰이 있는 에피소드** | **10 (24%)** |
| +15분 이내 관찰이 있는 에피소드 | 7 (17%) |

**Grade A 조건을 다 만족하는 에피소드는 사실상 없다.** 이것이 3차가 시간축을 못 잰 이유의 정량적 표현이다.

## 7. 앱에 필요한 최소 변화 — **설계안만. 구현하지 않는다**

기존 UI를 크게 바꾸지 않고 붙일 수 있는 최소 단위로 적는다.

### 7-1. 반응 추적 (기본)

```
[약 복용 기록] 저장 시
  └─ 체크박스 하나:  □ 이번 복용의 반응을 따라가기
       체크하면 → +30 / +60 / +90분에 기록 알림
       각 알림에서 「지금 기록」 한 번이면 output 입력 화면
       「이미 충분히 좋아졌어요」 → 그 시점 기록 후 추적 종료
       「건너뛰기」 → 그 점만 비우고 계속
```

### 7-2. 정밀 추적

```
추적 시작 시 선택:  ○ 기본 (+30 / +60 / +90)
                    ○ 정밀 (+15 / +30 / +45 / +60)
정밀은 아침 첫 복용에서 기본값으로 제안 (강제하지 않음)
+60분에 아직 낮으면 → 「+90분에 한 번 더 볼까요?」
```

### 7-3. 하강 중 복용

```
복용 기록 시 직전 상태의 trend가 falling 이면
  └─ 「지금 내려가는 중에 드셨어요. 최저점까지 따라갈까요?」
       예 → +10 / +20 / +30 / +45 / +60 / +90 알림
       기록 화면에 버튼 두 개 추가:
         「여기가 제일 낮았어요」  → nadir 표시
         「지금 올라오기 시작했어요」 → rebound 표시
```

### 7-4. 데이터에 추가될 필드 (제안)

| 필드 | 값 | 비고 |
|---|---|---|
| `trackingSession` | 복용 이벤트 id | 어느 복용의 추적인지 |
| `trackingPlan` | `basic` \| `precise` \| `decline` | 어떤 프로토콜이었나 |
| `plannedOffsetMin` | 30, 60, 90 … | **예정** 시각 |
| `actualOffsetMin` | 실제 값 | **저장은 언제나 실제 시각.** 예정 시각으로 반올림하지 않는다 |
| `nadirMark` / `reboundMark` | boolean | 사용자가 직접 누른 표시. **참고 라벨이며 ground truth 아님** |
| `trackingEnded` | `enough_on` \| `next_dose` \| `skipped` \| `completed` | 왜 끝났는지 — 절단 원인을 구분하기 위해 필요 |

`trackingEnded`가 특히 중요하다. **"기록이 없다"의 이유를 남겨야** 다음 분석에서
"관찰을 안 한 것"과 "이미 좋아져서 끝낸 것"을 가를 수 있다.

기존 `partial` 버튼과 `riseResult`(reached/delayed/partial/failed)는 **그대로 둔다.**
다만 3차·4차에서 확인한 대로 **참고 라벨일 뿐 분석의 1차 자료가 아니다.**
(사용자가 `failed`로 표시한 유일한 에피소드는 측정상 75까지 올랐다.)

## 8. 기록 부담 — 현실적인가

### 지금

| | |
|---|---|
| 상태 기록 | 137건 / 13일 = **하루 10.5건** |
| 레보도파 복용 | 42회 / 13일 = **하루 3.2회** |

### 프로토콜 적용 시

| 시나리오 | 하루 기록 수 | 지금 대비 |
|---|---|---|
| 모든 복용에 **기본형**(4점) | 3.2 × 4 ≈ **12.8건** | **1.2배** |
| 하루 한 번만 **정밀형**(5점) + 나머지 기본형 | 5 + 2.2×4 ≈ **13.8건** | **1.3배** |
| 모든 복용에 정밀형 | 3.2 × 5 ≈ 16건 + 연장 | 1.5배 이상 — **권하지 않음** |

**모든 복용에 기본형을 적용해도 지금과 거의 같은 부담이다.** 이미 하루 10.5건을 남기고 있기 때문이다.
문제는 기록의 **양**이 아니라 **배치**였다 — 같은 수의 기록이 상승 구간을 비켜나 있었다.

### 그래서 이렇게 권한다

| | |
|---|---|
| **모든 복용** | 기본형 (+30 / +60 / +90) |
| **하루에 한 복용만** | 정밀형 — 아침 첫 복용을 우선 |
| **하강 중 복용이 생기면** | 그때만 §5 프로토콜 |

정밀형을 매 복용에 쓰지 않는 이유는 통계가 아니라 **지속 가능성** 때문이다.
며칠 만에 그만두는 정밀 기록보다 2주 이어지는 기본 기록이 낫다.

### 현실적으로 어려울 것으로 보이는 지점

- **심야 복용(02~04시).** 3차에서 이 시간대는 대부분 기록 1건이었다. 자다 깨서 4점을 남기기는 어렵다. **이 구간은 기본형도 무리라고 보고, 복용 직전과 +60분 두 점만 목표로 낮춘다.**
- **21시 서방형.** 1시간 뒤 22시 IR이 들어와 어차피 관찰이 끊긴다. **서방형 단독 평가는 이 복용 간격에서는 포기하고**, 대신 두 복용을 한 구간으로 보는 편이 정직하다.

## 9. 앞으로 확보할 최소 사례 수 (탐색적 목표)

**연구 통계가 아니라 반복성 확인이 목적이다.** 한 사람 안에서 같은 모양이 되풀이되는지만 본다.

| 유형 | 목표 | 비고 |
|---|---|---|
| 정상 반응 (Grade A) | **5건 이상** | 3차의 22시 IR처럼 같은 시각·같은 제형으로 |
| Delayed ON 의심 | **5건 이상** | 절단되지 않은 첫 상승 시각이 있는 것만 |
| Incomplete ON 의심 | **5건 이상** | 최고점이 확실히 잡힌 것만 |
| 하강 중 복용 | **5건 이상** | 최저점과 반등이 둘 다 있는 것만 |
| **ON Failure** | **숫자를 채우지 않는다** | 드물 수 있다. 억지로 채우면 `not evaluable`을 후보로 올리게 된다 |

**같은 시각대 안에서 모아야 한다.** 3차에서 22시 IR 90 / 02시 IR 50 / 21시 CR 30으로
시각대 차이가 다른 어떤 차이보다 컸다. 시각대를 섞으면 시각대 효과를 Delayed/Incomplete로 잘못 읽는다.

기간은 **2주**를 제안한다. 하루 3.2회 복용 × 14일이면 기본형만으로도 45 에피소드가 쌓이고,
그중 정밀형이 14건(하루 한 번)이면 Grade A 목표를 채우기에 충분하다.

## 10. 6차(전향적 재현성 검정)에서 할 일

새 프로토콜로 2주 기록한 뒤, **기존 기록과 나란히 놓고** 다음을 본다.

| # | 확인할 것 | 성공 기준 |
|---|---|---|
| 1 | **좌측 절단이 실제로 줄었는가** | 첫 상승 시각이 첫 관찰 시각과 **다른** 에피소드가 생겼는가. 지금은 0/12다 |
| 2 | Grade A 비율 | 지금 사실상 0% → 목표를 정하지 않고 **얼마나 되는지만** 본다 |
| 3 | **시간축에 군집이 보이는가** | 절단이 풀린 첫 상승 시각의 분포에 틈이 있는가. **없으면 없다고 적는다** |
| 4 | 높이축 결과가 유지되는가 | 22시 IR의 최고 90이 새 프로토콜에서도 재현되는가 |
| 5 | `decline → nadir → rebound` 재현 | 최저점이 이른 시점에 오는 것이 반복되는가 |
| 6 | `not evaluable` 비율 | ON Failure 후보 중 몇 건이 실제로 검토 가능해졌는가 |

**분석 도구는 이미 있다.** `scripts/analyze-phase3.mjs`를 새 백업에 그대로 돌리면
같은 측정이 나오고, 3차 결과와 직접 비교할 수 있다. 6차에서 새 스크립트를 만들 필요는 없다.
다만 `trackingPlan` · `trackingEnded` 필드가 생기면 그것을 읽는 부분만 추가하면 된다.

## 11. 이번 단계에서 하지 않은 것

- 약 복용시간 변경 권고 · 용량 변경 · 치료 전략 제안 — **없다**
- 자동 진단 · 자동판정 알고리즘 — **없다**
- 임의 cutoff 확정 — **없다.** Grade 기준은 기록 완성도이지 반응 기준이 아니다
- 다른 환자 데이터 통합 — **없다**
- 홈페이지 문구 수정 — **없다**
- 앱 코드 구현 — **없다.** §7은 설계안이다

이번 단계는 **측정 프로토콜 설계뿐**이다.
